# 电脑原生跟随

已接入捕获到的跟随模式选择、启动和空负载停止。协议证据来自 2026-11-02/03 DJI Fly 实飞；PC 启动、停止和降落已有操作者实机验证；图传仍存在真实缺帧后的冻结限制。无需联网，语音入口尚未接入。

## 准备与启动

让飞机落地，相机能看到人物。退出手机 DJI Fly 的飞机连接和其他电脑控制台，将电脑连接飞机 Wi-Fi。在项目根目录运行：

```powershell
python .\extras\follow_console.py --connect --video
```

`--video` 可省略。浏览器打开终端输出的本地预览地址，可查看图像和主体框；框本身不等于已验证锁定。程序复用原有 `.state/routing-sequence.json`，不要删除或用旧快照覆盖。

初始化成功后逐条输入：

```text
准备
跟随
确认
```

“准备”仅选择跟随模式并核对完整回显，不发启动。随后“跟随→确认”必须在10秒内完成，可能自动起飞。跟随人物由飞机自动识别；本入口不支持点选人物、设置距离或高度。收到00仅说明请求得到回复，实际跟随需结合任务执行状态与目视观察。

## 首次验收

在安全空旷处短时验证：启动后缓慢走几步，确认飞机确实跟随；输入 `停止`（或 `停止跟随`），确认飞机悬停；再输入 `降落`。停止本身不要求落地，也不会自动重启跟随。

降落会先取消未完成的启动；原生任务若仍活跃或状态不明，会尝试停止再请求降落。任务已新鲜回报退出时跳过重复停止。持续显示降落状态，仅在本控制台明确发起且已收到成功回复的降落、并满足已有低空降落状态条件时，允许自动补发一次抓包对应的后续降落确认。不会把00回复当成落地。

目视确认落地、电机停止后输入 `退出`。首版每次连接只启动一轮跟随；再次运行前先落地退出。退出时如未能确认落地会尝试停止和降落，但不能保证已经落地，不应依赖退出替代降落及观察。若动作未按预期执行，用原厂方式接管并保留记录。

## 记录

- `状态` 查看通信、任务及降落回报。
- `主体` 查看自动识别的候选与跟踪框数据。
- 退出时打印 `captures/control-attempt-*.json` 会话记录。
- `--video` 同时保留有大小限制的视频诊断至 `captures/video-diagnostics`。
- 不带 `--connect` 仅打印离线帮助，不连接飞机。
