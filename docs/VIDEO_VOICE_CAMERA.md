# 视频、离线语音、相机与原片下载

本次将这三组能力从完整版本 `cf8ccf7` 补回当前模块结构。电脑实现可作运行与迁移参考，不能直接替代鸿蒙媒体/语音接口；没有新增实机验证结论。

## 1. 目录和依赖

| 能力 | 文件 | 依赖/平台 |
| --- | --- | --- |
| 视频分片 | `core/video_packets.py` | 标准库，不解码 |
| HEVC 解码与浏览器预览 | `extras/video_stream.py` | PyAV、Pillow；本机 HTTP |
| 离线意图与动作 | `extras/voice_commands.py`、`voice_motion.py`、`voice_control.py` | 标准库 + 核心会话 |
| Windows 识别适配 | `extras/offline_speech.py`、`windows_speech.ps1` | Windows 已安装中文语音引擎 |
| 联合演示入口 | `extras/voice_console.py` | Windows 语音；可选视频 |
| 相机控制与观察 | `core/native_camera.py`，`flight_controller.py` 的相机接口 | 复用已有 UDP 会话 |
| 相册协议与流重组 | `core/media_directory.py`、`media_directory_link.py` | 标准库 |
| 原片下载/校验 | `core/media_transfer.py` | HTTP/TCP；JPEG 完整解码需 Pillow |

安装 `requirements-extras.txt` 后运行 `python run_tests.py --extras`。安装依赖和离线测试不会连接飞机。

## 2. 电脑运行方式

先让原控制台退出，接续该设备最新 `.state/routing-sequence.json`，不要从低 counter 重新使用旧注册身份。这个状态文件不在 Git 中，需交接方另给。新入口在缺少状态时会拒绝连接。

```powershell
# 查看帮助，不启动麦克风或飞机连接
python extras/voice_console.py --help

# 仅离线识别预览，不连接飞机
python extras/voice_console.py --listen

# 飞机 Wi-Fi 已连接，状态文件已接续后
python extras/voice_console.py --connect --video
```

初始化完成后，键盘输入 `启用语音`。浏览器打开程序打印的 `http://127.0.0.1:端口/`；此预览无需公网。口令也可在键盘输入；`--text` 是无飞机的键盘预览，不是另一个同时运行的控制会话。

| 口令 | 行为 |
| --- | --- |
| 起飞 → 确认 | 检查本轮状态后起飞 |
| 向前飞一点 / 上升三秒 | 时长动作，结束回中 |
| 环绕两米 → 确认 | 模式、半径写回和独立读取检查后原生启动 |
| 停止 / 停止环绕 | 取消当前工作、回中，并按状态尝试原生任务停止 |
| 拍照 | 核对状态/校时/前置模式，再请求拍照 |
| 开始录像 / 停止录像 | 请求机内开始或停止录像，并继续观察状态 |
| 相册 | 读取飞机实时目录 |
| 下载最新照片 / 下载最新录像 | 从实时目录选择已完成文件并下载原片 |
| 降落 | 取消/停止当前工作并尝试降落，仍需确认实际落地 |

原片写到仓库根目录的 `captures/pc-downloads/`，运行日志仍在 `captures/`；这些输出不会提交到 Git。停止录像与停止飞行动作是不同口令，不能混为一个状态。

## 3. 视频接入和手机替换点

`VideoReceiver` 必须在 `FlightController.connect(..., video_receiver=receiver)` 之前创建，以收到起始参数集；`submit(raw)` 仅非阻塞入队，解码在独立 worker。队列有界，出错或队满不能阻塞控制接收线程。

Python 路径：完整分片 → HEVC Annex-B → PyAV → Pillow JPEG → 仅绑定 `127.0.0.1` 的 HTTP 预览。网页显示解码数、最新画面年龄、停收/冻结状态。组帧器与核心共用，不维护第二份分片算法。

历史冻结原因之一是仅时序变化的 VPS/SPS 更新使解码器静默停止输出。`_TimingParameterFilter` 只对已识别且签名匹配的情形抑制更新；其他格式或实际参数变化仍透传。这不是一律丢弃 SPS，也不等于无线丢包已经解决。参考链或初始参数集丢失仍可能等待下一关键帧；没有猜测或发送请求关键帧的协议。

鸿蒙迁移时复用 `video_packets` 的组帧规则，将完整 HEVC 数据交给目标设备支持的解码/显示能力，替换 PyAV、Pillow 与本机网页。分别验证参数集变化、分辨率变化、丢参考帧、晚接收、恢复和显示延迟。若展示的是旧帧，界面应明确显示画面年龄。

## 4. 离线语音接入和手机替换点

识别器只输出文本、置信度和时间戳；`voice_commands` 做单意图解析，`voice_motion` 做时长/标定规划，`voice_control` 做确认、状态检查、取消与实际执行。默认预览，必须在键盘启用；拒绝过期、低置信度、多动作歧义和否定指令。

普通方向最长 10 秒，“一点”默认 0.5 秒。米数和转角需要方向/轴对应的实测标定；文件不会通用于其他设备或环境。起飞和环绕需短口令“确认”；停止、降落走独立取消路径，不排队等长动作。

鸿蒙端保留这三层逻辑，**替换 Windows 识别适配**，不要移植 PowerShell/System.Speech。要在目标手机上验证系统或第三方离线中文识别是否可用、所需授权、麦克风权限和前后台限制；仓库没有提供鸿蒙识别 SDK。云端 Agent 可代替意图来源，但仍要经过同一本地执行校验。

## 5. 相机协议

相机操作通过原有可靠 UDP 会话发送，sender `02`，常规 receiver `01`，command set `02`，请求标志 `40`。不需要建立第二个控制会话。

| 动作 | command id | payload |
| --- | --- | --- |
| 校时 | `54` | `<H5Bh`：年 u16、月/日/时/分/秒各 u8、时区分钟偏移 i16，小端共 9 字节 |
| 照片模式 | `ff` | `003700010100` |
| 视频模式 | `ff` | `003700020000` |
| 拍照 | `01` | `01` |
| 开始录像 | `02` | `01` |
| 停止录像 | `02` | `00` |

拍照前置参数是另一接收端 `17` 的 `03/f9`，payload `878867a309000000`，需匹配写入回显。它与环绕选择的 `...05000000` 不同；原生任务进行中不能随意切换。

`CameraObservation` 校验并读取 `02/80` 状态，保留模式、录像候选/原始状态、校时标志及时间。未校时时先校时并等待新鲜的已同步遥测；校时 ACK 本身不等于状态同步。录像请求 `00` 也不证明持续录制或文件已经保存；需观察机载状态及最终媒体目录。

迁移时保留 `NativeCamera` 的互斥、取消和不打断录像规则，下载也不能占住飞行状态锁。相机的未知枚举和新固件格式应明确报告，不能当成 idle。

## 6. 相册与原片

读取目录：`02→01`，`00/26`，payload 见 `make_directory_request()`。当前只改变观测到的 u16 album session 字段。请求 ACK 与目录数据分开；目录 `00/27` 从 channel 3 的可靠数据流到达，DUML 可跨 UDP 包，必须先按传输顺序重组，再做 CRC 和相册分片校验。

相册 session、相册分片 index、DUML seq 和外层可靠序号是四个不同概念。保留过期会话隔离、重复/冲突检测、结束标志、缺片检查及大小限制。当前实现仅覆盖已观察到的文件名与元数据布局；大小未知的项目拒绝下载。

实时下载使用飞机 `192.168.2.1:80` 的只读 HTTP GET：

```text
/v2?storage=1&path=DCIM/DJI_001/<已核验的文件名>
```

当前样本 JPEG 使用完整 GET，MP4 按观测方式分为五段 Range，最后一段包含余数。逐段核对状态码、Content-Length、Content-Range 和一致的强 ETag，不跟随重定向；总长度与实时目录一致后校验 JPEG 解码或 MP4 box 结构。最终原子发布，拒绝覆盖同名文件。MP4 结构通过不代表逐帧均已解码。

手机端除了控制 UDP，**下载的 TCP/HTTP 也必须走飞机 Wi-Fi**；云端 Agent 才走移动网络。不能只绑定 UDP 后让下载请求错误地走公网默认网络。

Python 参考下载器会将数据组装到内存，最大文件限制为 512 MiB；手机端建议流式写临时文件、增量校验后原子发布，保留取消、不覆盖和“不完整文件不能冒充原片”的语义。`os.link`、本机路径和 Pillow 校验都需要平台替换。

## 7. 实测边界

已有录像保存到机内、PC 原片下载成功的操作者反馈；补齐前置参数后的 PC 拍照仍以最后现场验证记录为准，不能仅凭代码恢复宣布成功。此次增加的是源码、集成与回归验证，没有执行新的拍摄、录像、下载或飞行动作，也没有完成鸿蒙端编译和真机测试。
