# 离线中文语音控制

## 新增：语音环绕、半径和相机预览（2026-10-29）

电脑端键盘原生 **2 米环绕已由操作者实飞确认完成**。语音入口沿用同一原生任务，不用八方向动作拼接圆周。新增语音组合及其他半径尚待实机验证。

先让飞机落地并退出其他控制台，电脑连接飞机 Wi-Fi，在工作区根目录运行：

```powershell
.\.抓包环境\Scripts\python.exe .\开发基地1\tools\voice_console.py --connect --video
```

初始化完成后，键盘输入 `启用语音`。浏览器打开程序打印的 `http://127.0.0.1:端口/` 地址看相机；不需要互联网。不需要画面时去掉 `--video`。

| 口令 | 行为 |
| --- | --- |
| 半径五米 / 设置环绕半径五米 | 设置下次环绕半径，不启动飞机 |
| 环绕 → 确认 | 按当前半径启动；默认 2 米 |
| 环绕五米 → 确认 | 本次改为 5 米再启动 |
| 准备环绕 | 仅写入、读取半径，不启动 |
| 停止环绕 / 停止 | 取消未发送操作，回中并发送原生任务停止 |
| 降落 | 尝试停止任务，再请求降落；仍需观察实际落地 |

半径支持 **2–10 米**，如 `环绕三点五米`。准备阶段逐项核对模式回显、半径写入回显、独立读取值；不一致则不启动。确认窗口 10 秒，只需说“确认”；改半径会取消之前的待确认请求。其他半径是按浮点参数格式扩展，不能视为均已实飞验证。

**环绕可能从地面自动起飞，需让相机看得到人物，并留足整个圆周空间。** 任务进行或状态不明时，不接受方向动作或半径修改，先停止任务。环绕自动起飞不会伪造普通起飞确认。停止环绕后，程序等待匹配停止回复及之后的新鲜任务停止、悬停飞行状态，才允许八方向动作；实际效果仍需实机验证。落地后可直接说“起飞→确认”或“环绕→确认”；程序核对新鲜电机停止和任务结束状态后开启新一轮，无需重连。飞机已在空中时，“起飞”只提示当前状态，不重复发起飞。

已从原始环绕抓包解码出 **1280×720 HEVC** 画面，证明视频能传回电脑。此次新增实时浏览器预览已完成本机测试，尚待实机预览验证；丢包后可能需等待下一个关键帧。画面显示帧龄，长时间不更新不代表飞机静止；用目视核对。

日志沿用 `captures/voice-session-*.json` 和 `control-attempt-*.json`。预览不自动录制视频，不保存音频。

电脑连接飞机 Wi-Fi 后，本程序仍可工作。识别使用电脑已安装的 Windows 中文语音引擎，不调用在线接口。语音在本机处理；只保存识别文字、执行结果和原有飞行记录，不保存录音。

下列命令均在项目根目录 `无人机控制 2` 的 PowerShell 中运行。无需修改系统脚本执行策略。

## 1. 先试语音预览

```powershell
.\.抓包环境\Scripts\python.exe .\开发基地1\tools\voice_console.py --listen
```

看到预览提示后，对电脑默认麦克风说“向上飞一点”“向前飞十米”“停止”。屏幕显示识别文字及置信度；此模式不连接飞机、不发动作。未标定的米数会提示补标定。输入 `退出` 结束。

识别器加载检查（不使用麦克风）：

```powershell
.\.抓包环境\Scripts\python.exe .\开发基地1\tools\voice_console.py --check-speech
```

麦克风不可用时检查 Windows 的默认输入设备及桌面应用麦克风权限。语音程序需要在普通用户桌面会话中运行；受限工具环境可能无法访问 Windows 语音组件。

## 2. 连接飞机后使用

关闭原来的 `flight_console.py`，电脑连接飞机 Wi-Fi，再运行：

```powershell
.\.抓包环境\Scripts\python.exe .\开发基地1\tools\voice_console.py --connect
```

等待“飞机初始化成功”，然后**用键盘输入 `启用语音` 并回车**。只说“启用语音”不会开启执行。

| 说出的口令 | 动作 |
| --- | --- |
| 起飞，然后在 10 秒内说“确认” | 两步确认后起飞 |
| 向前飞一点 / 向后飞一点 | 前进 / 后退 0.5 秒 |
| 向上飞一点 / 向下飞一点 | 上升 / 下降 0.5 秒 |
| 左移一点 / 右移一点 | 平移 0.5 秒 |
| 左转一点 / 右转一点 | 转向 0.5 秒 |
| 向前飞十秒 / 左转五秒 | 指定时间，单次最长 10 秒 |
| 向前飞十米 / 向左转九十度 | 用相应方向的实测速度估算，未标定则拒绝 |
| 停止 / 回中 / 悬停 | 取消后续分段，立即发送四轴中位 |
| 降落 | 中断方向动作并发送降落；`00` 只表示指令回复，后续状态另行提示 |
| 暂停语音 | 取消方向动作并关闭语音执行；键盘降落仍可用 |
| 状态 | 显示当前连接与飞行状态 |

同一连接重飞：说“降落”，目视确认已落地后，说“起飞”或“再次起飞”，再在 10 秒内说“确认”。程序要求新鲜落地状态；已落地时降落回复为 02 不再永久锁定下一轮。无需退出重连。所有待确认的语音操作都可用“确认”应答；没有待确认操作、超过 10 秒或已经停止时，说“确认”不会起飞。原有的长确认口令仍兼容，但不再要求使用。

键盘也能输入上述动作。**`停止`、`降落`、`退出` 的键盘入口保持可用。** 输入 `退出` 会关闭会话，沿用原控制器的退出时尝试降落行为；先目视确认落地再退出。说“退出”只暂停语音，不关闭会话。

每次只接收一个动作，执行中其他方向不会排队。停止和降落优先于方向动作；“停止”用于回中，不能撤销飞机已经接受的自动起飞或自动降落。普通口令置信度需达到 0.70；明确的“降落”和回中类口令使用 0.50 阈值，以减少漏掉这两类口令。所有语音仍要求结果不超过 3 秒，否定口令不执行。应逐句说，勿把多个动作连成一句。

降落后程序持续观察飞机状态，区分“指令已回复”“飞机回报降落模式”“降落已中断且电机仍在运转”“飞机回报电机已停止”。电机停止状态也仍需目视确认落地。数据过期会明确提示不能确认。监测只提供反馈，不自动重发降落或改变飞行指令；收到 `00` 不能当作降落完成。降落请求后的方向锁定保持，若自动降落中断，应使用原厂控制方式接管落地。

2026-10-29 16:24 的实际故障记录中，四条降落指令均获同序号 `00`，飞机状态每次只短暂进入降落模式，约 0.2–0.3 秒后恢复悬停。16:25:25 才在用户手动落地后出现电机停止。降落为何退出仍未确认，当前修正不等于该实飞故障已解决。

## 3. 标定米数和角度

没有默认飞行速度。先用原控制台或语音中的秒数执行同一方向的短动作，测量实际位移；落地后录入结果。各方向独立标定，转向录入角度。前进标定不能代替后退、上升或转向标定。

例如，**只有实际测得前进 1 秒移动 0.8 米时**，才录入以下值；请替换成自己的实测结果：

```powershell
.\.抓包环境\Scripts\python.exe .\开发基地1\tools\voice_console.py --calibrate 前进 --seconds 1 --meters 0.8
```

转向同理，例如实际测得左转 1 秒约 30 度时：

```powershell
.\.抓包环境\Scripts\python.exe .\开发基地1\tools\voice_console.py --calibrate 左转 --seconds 1 --degrees 30
```

标定模式只保存数据，不连接飞机。每方向取最近 5 次样本速度的中位数，保存在 `.state/voice-calibration.json`。不要删除原有 `.state/routing-sequence.json`。

距离指令单次最多 10 米，转向最多 180 度，预计动作总时间最多 20 秒；超过限制拒绝执行。执行分为最长 10 秒的小段，段间回中 0.15 秒。标定样本的实际动作时间也支持最长 10 秒。“一点”为 0.5 秒，无需标定。长动作期间仍可说或键盘输入“停止”“降落”来中断。

**估算不等于定位控制。** 加减速、分段回中、风和制动距离都会造成偏差，回中也不保证瞬间停住。先在空旷处验证短动作；这里没有障碍检测和精确到点功能。语音识别有延迟，保留键盘停止和降落作为即时操作入口。
