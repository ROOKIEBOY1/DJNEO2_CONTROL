# 拍照、录像与原片传到 PC（2026-10-30）

目标是复用已验证的连接，在 PC 上触发飞机原生拍照、开始录像、停止录像，再把飞机保存的原文件下载到 PC。现有 720p 图传预览继续保留；图传截图或录屏不能作为已经实现原片下载的证据。

## 当前证据和进度

操作者确认上一阶段的飞行、环绕接续与视频问题已解决。

已有抓包中能看到 `02 → 01` 的相机命令集通信，包括 `02/FF`、`02/D8`、`02/E8` 等；没有此次标注的拍照、手动开始/停止录像和原片下载样本，暂不为这些通信猜测动作含义，不将其加入可发送命令。

已增加：

- `tools/capture_media_session.py`：通过 USB 采集 iPhone 网络，保留所有端口，包括 TCP 文件传输。默认 240 秒、512 MiB，可 Ctrl+C 或用停止标记结束；不会覆盖旧抓包，结束时关闭文件和设备连接。不连接飞机控制接口、不发送飞行或相机动作。
- `tools/analyze_camera_media.py`：读取本地 pcapng，统计 IPv4 TCP/UDP 通道、相机候选 DUML 形状及有限 HTTP 请求线索。尚不实现 TCP 重组、TLS 解密或原文件提取；IPv6、IP 分片等明确计入未支持统计。
- `captures/camera-media-baseline-20261030.json`：对旧主动停止环绕抓包的离线基线分析，34405 包、37 种相机候选形状，未发现 HTTP 请求线索。

190 项自动测试通过，包括新工具的超时、停止、关闭、文件防覆盖、非 9003 通道保留和解析边界测试。实际手机采集仍未开始：当前 USB 设备列表为空，Windows 未列出 Apple/iPhone 设备，已请操作者重新插拔并解锁。

## 下一步采集

1. 飞机留在地面，退出 PC 飞控和语音程序。
2. iPhone 连接电脑 USB 并解锁、信任；手机连接飞机 Wi-Fi，打开 DJI Fly。PC 可保持上网网络。
3. 检测成功后启动抓包，再通知操作者开始动作。不要在抓包开始前操作。
4. 在 DJI Fly 拍一张照片，等约 3 秒；开始录像，录约 10 秒后停止，再等约 3 秒。
5. 进入飞机相册，把刚才这张照片、这段视频分别下载到手机；若提供预览/原片选择，选择原片，等待下载完成。
6. 操作者回复完成并说明照片、录像及两次下载是否成功。停止采集，先对比请求、同序号回复、媒体状态和文件通道，再实现 PC 控制和下载。手机下载步骤是为了确认原片传输协议，最终目标仍是 PC 直接获取文件。

在工作区根目录可运行：

```powershell
.\.抓包环境\Scripts\python.exe .\开发基地1\tools\capture_media_session.py --capture
```

程序明确输出“抓包已开始”才表示已经采集。停止某次采集时，传入它的 `.capture.json`：

```powershell
.\.抓包环境\Scripts\python.exe .\开发基地1\tools\capture_media_session.py --stop <本次会话.capture.json>
```

离线初步分析：

```powershell
.\.抓包环境\Scripts\python.exe .\开发基地1\tools\analyze_camera_media.py <本次抓包.pcapng>
```

下一阶段再接入“拍照 / 开始录像 / 停止录像 / 下载最新照片 / 下载最新录像”等操作；尚无样本的动作和下载接口不作为已实现能力报告。
